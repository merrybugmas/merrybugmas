## Ⅱ. 문제정의 및 프로젝트 목표

**○ 해결과제 및 프로젝트 목표**

장애가 나면 운영자는 트래픽(Grafana), 에러(Sentry), 자동 수정 봇(sentry-bot)의 진행 상황을 서로 다른 화면에서 맞춰 봐야 한다. 지금 무엇이 터졌는지, 봇이 무엇을 처리 중인지, 사람이 봐야 할 것은 무엇인지를 한눈에 알기 어렵다. 봇이 왜 그렇게 판단했는지는 더 보이지 않아, 자동화를 믿고 맡기기 어렵다.
MERRY BUGMAS 는 세 화면을 하나의 게임 장면으로 합친다. 트래픽은 상점 앞 대기열, 미해결 이슈는 쥐, 봇은 쥐를 잡는 호두까기 병정이다. 목표는 ① 숫자를 읽지 않아도 상황이 보이게 하고 ② 에이전트의 판단 근거를 화면에 남기며 ③ 운영자가 채팅 한 줄로 에이전트를 지휘하게 하는 것이다.

**○ 주요 대상 사용자·활용 방안**

- 온콜 개발자: 장애 대응 중 트래픽·에러·봇 상태를 한 화면에서 보고, 채팅으로 "WEB-2B1 먼저 처리" 처럼 우선순위를 바꾼다.
- 운영·프로덕트 담당자: 팀 모니터에 띄워 두고 줄 길이와 쥐 수로 서비스 상태를 직관적으로 파악한다.
- 자동화 봇을 도입하려는 팀: 봇이 이슈를 어떻게 판정(fixable / noise / 사람 필요)했고 왜 그랬는지를 기록으로 확인하며 신뢰를 쌓는다.
- 신규 입사자 교육: "트래픽이 늘면 에러가 늘고, 봇이 처리하고, 일부는 사람에게 넘어온다"는 운영 흐름을 게임으로 설명한다.

**○ 프로젝트 추진 목적 및 구현 목표**

추진 목적은 AI 에이전트를 운영에 들일 때 생기는 두 가지 벽, 즉 "에이전트가 뭘 하는지 안 보인다"와 "에이전트에게 말로 시킬 수 없다"를 낮추는 것이다.
구현 목표는 세 층이다.
1) 시각화: 터미널에서 의존성 없이 도는 픽셀아트 대시보드. 서비스 6개 × 시나리오 3개(트래픽·Sentry·개요)를 게임처럼 골라 본다.
2) 운영자 에이전트(Codex): AGENTS.md 를 도구 사용 규약으로 삼아, 사람 말을 대시보드 명령으로 바꾸고 현황을 숫자로 답한다. 자율 모드에서는 사람 없이 30초마다 상황을 판단해 지시한다.
3) 병정의 두뇌(OpenAI API): 자연어 명령 해석, 이슈 트리아지와 근거·수정 요약, 운영 브리핑을 구조화된 JSON 으로 받아 게임 동작에 바로 연결한다.
그리고 API 키가 없거나 호출이 실패해도 대시보드가 멈추지 않도록 키워드·mock 판정으로 이어지게 하는 것까지가 목표다.

## Ⅳ. AI 기술 활용 및 적용 방식

**○ OpenAI API·Codex 등 활용 기술 및 적용 기능**

- **Codex CLI — 운영자 에이전트**: 대시보드 옆 창에서 Codex 가 레포의 `AGENTS.md` 를 읽는다. 이 문서는 Codex 용 도구 사용 규약이다. 어떤 명령(`./market status · tell · focus · start · view · brief · say`)이 있는지, 답하기 전에 반드시 status 를 읽고 숫자로 답할 것, 코드를 고치지 말 것을 적어 두었다. 사용자는 "검색 쪽 버그 보여줘", "다들 뭐 하고 있어?" 처럼 말하기만 하면 된다.
- **Codex exec — 자율 운영 모드**: `tools/codex-autopilot.sh` 가 30초마다 `codex exec` 를 실행한다. Codex 는 현황을 읽고 가장 급한 일을 골라 최대 2개 명령을 내린 뒤, 판단 근거를 대시보드에 띄운다.
- **OpenAI API — 병정의 두뇌** (`ai.py`): Responses API 와 strict JSON Schema(Structured Outputs)로 세 가지 판단을 받는다.
  ① 명령 해석: 문장 + 현황 JSON → {병정, 행동, 이슈 ID, 대답}
  ② 트리아지: 이슈 제목 → {fixable / noise / needs-human, 근거, MR 수정 요약}
  ③ 브리핑: 현황 JSON → {요약 3줄, 권고}

**○ 프로젝트 내 AI 기술의 역할 및 주요 동작 방식**

(그림: `docs/images/architecture.png`)

1. 사람(또는 자율 모드)이 Codex 에게 말한다. Codex 는 `./market status` 로 `.runtime/state.json`(1초마다 갱신)을 읽고 판단한다.
2. Codex 가 `./market tell 진저 …` 를 실행하면 `.runtime/cmd` 를 거쳐 대시보드에 바로 반영된다.
3. 대시보드는 명령 문장을 OpenAI API 에 넘겨 구조화된 의도로 받는다. 새 이슈(쥐)가 생기면 트리아지를 요청하고, 병정은 판정이 올 때까지 "AI 판정 중" 말풍선으로 기다린다.
4. 판정 근거와 수정 요약은 작전 로그(🧠)와 잡은 쥐 기록에 남아, 에이전트가 왜 그렇게 했는지 사람이 확인할 수 있다.
5. 안정성 설계: API 호출은 백그라운드 스레드에서 하고, 결과는 메인 루프가 매 프레임 반영해 화면이 멈추지 않는다. 사람이 내린 판정은 늦게 온 AI 판정이 덮지 않는다. 8초 안에 판정이 없으면 기본 판정으로 진행한다. 형식이 틀린 응답은 버린다. 429·5xx 는 재시도한다. 키가 없거나 실패하면 키워드 해석·mock 판정으로 이어진다.

## Ⅴ. 프로젝트 구현 결과 및 완성도

**○ 프로젝트 구현 결과 및 완성수준**

- **실제 작동 범위**: `python3 xmas_market.py` 하나로 타이틀부터 메뉴, 6개 서비스 × 3개 시나리오 스테이지까지 모두 동작한다. 외부 패키지와 API 키가 필요 없다. `OPENAI_API_KEY` 를 넣으면 AI 병정 모드(명령 해석·트리아지·브리핑)가 켜지고, `./run-with-codex.sh` 로 Codex 채팅과 나란히 띄운다.
- **테스트·검증**: `tests/test_smoke.py` 29개 테스트가 모두 통과한다(1.5초, 네트워크 없이).
  - 18개 화면 조합 렌더
  - 키워드 명령
  - 가짜 OpenAI 응답으로 확인하는 명령 해석·트리아지·브리핑
  - API 실패 시 폴백, 사람 판정 우선, 판정 타임아웃, 형식 오류 응답, 429 재시도, 판이 바뀐 뒤 도착한 결과
  - 녹화·재생, 가짜 Sentry 응답으로 확인하는 실연동(중복 방지·가짜 쥐 차단·읽기 실패 시 mock 폴백)
  - 가짜 /metrics 로 확인하는 트래픽 실연동(카운터 증가분 → rps, 서버 재시작·읽기 끊김, 가짜 급증 차단)
  - 구현 뒤 [작성: 누가 리뷰했는지 — 사람/AI 도구명] 코드 리뷰를 거쳐, 지적된 결함 5건(사람 판정 덮어쓰기·판정 대기 고착·이상 응답 처리 등)을 고치고 회귀 테스트로 고정했다.
- **AI 트리아지 정확도 평가 (실제 API)**: 정답을 붙인 Sentry 이슈 제목 32건(fixable 14 · noise 10 · needs-human 8)을 `tools/eval_triage.py` 로 gpt-5-mini 에 판정시켰다. 결과는 **정확도 29/32 = 90.6%**, 평균 응답 4.2초, 호출 실패 0건이다(`docs/eval/triage-gpt-5-mini.md`). 사람이 꼭 봐야 하는 needs-human 8건은 모두 맞혔다. 틀린 3건(브라우저 저장소 차단, JSON 대신 HTML 응답, 출처 불명 Promise 거부) 중 2건은 사람에게 넘기는 보수적 오판이고, 1건(fixable → noise)은 실제 버그를 놓치는 방향이다. 평가셋은 직접 만든 32건(제목만, 1회 실행)이고 프롬프트 예시와 유형이 겹쳐, 실제 이슈에서는 더 낮을 수 있다. 시연 화면(`docs/images/ai.png`·`ai-history.png`)도 실제 API 호출로 찍었다(13회 호출, 실패 0).
- **Sentry 실연동 검증**: 테스트용 Sentry 프로젝트에 데모 웹앱(merrybugmas/demo-web, 일부러 심은 버그 7종)을 붙였다. 브라우저에서 난 실제 에러가 Sentry 이슈가 되고, 대시보드(`--live`)가 그것을 읽어 쥐로 만드는 것까지 확인했다. 실제 서비스의 이슈로는 검증하지 않았다.
- **트래픽 실연동 검증**: 같은 데모 서버의 `/metrics` 를 읽었다. 부하 생성기로 25 → 110 → 25 rps 를 주자 대시보드 rps 가 그대로 따라가고 줄이 인파 경보까지 늘었다. 로컬 서버 한 대 기준이며 실제 서비스 트래픽으로는 검증하지 않았다.
- **현재 제약사항**:
  - 기본 실행은 트래픽·이슈 모두 mock 이다. `--live` 에서만 실제 Sentry 이슈와 실제 서버 rps 를 쓰며, 테스트 프로젝트·로컬 데모 서버로만 검증했다.
  - 트리아지 입력은 이슈 제목뿐이다. 명령 해석·브리핑은 정량 평가를 하지 않았다.
  - Codex 연동은 규약·스크립트까지 구현했고, 지출 한도로 최종 실행 검증을 못했다.
  - 병정의 fix·review·MR 은 연출이며, 실제 코드 수정 MR 은 만들지 않는다.
  - macOS · Python 3.9 에서 확인했다. Linux · Python 3.8 은 문법 호환만 확인했다(Windows 는 WSL).

## Ⅵ. 실용성 및 문제 해결 효과

**○ 주요 활용방안 및 문제 해결 효과**

- **장애 대응 상황판**: 배포 직후 에러가 몰리면 쥐 떼가 나오고, 병정이 자동으로 분류한다. 운영자는 needs-human 우리에 갇힌 쥐만 보면 된다. 확인해야 할 화면이 셋(Grafana·Sentry·봇 로그)에서 하나로 준다(기대 효과). 평가 32건 기준으로 AI 가 사람에게 올린 것은 10건이라 운영자가 볼 이슈가 약 69% 줄었고, 사람이 봐야 할 8건은 하나도 놓치지 않았다(직접 만든 평가셋 기준).
- **봇 판단의 투명성**: 모든 판정에 근거 한 줄이 붙고 기록으로 남는다. 잘못된 판정은 채팅 한 줄("WEB-2B1 사람에게")로 바로잡고, 그 결정은 AI 가 다시 덮지 않는다. 자동화를 사람이 감독하는 구조다.
- **말로 하는 운영**: 명령어를 외우지 않아도 "제일 오래된 쥐부터", "검색 쪽 503 에러 난 거" 같은 표현으로 지시할 수 있다.
- **실연동 비용이 낮음**: Sentry 는 이미 붙였다. `.env` 에 토큰·조직·프로젝트 세 값을 넣고 `--live` 로 띄우면 그 프로젝트의 미해결 이슈가 쥐가 된다(읽기 전용이라 운영 중인 Sentry 에 영향이 없다). 트래픽도 서버의 `/metrics` 주소 하나만 넣으면 실제 rps 로 줄을 세운다(Prometheus 형식 카운터가 있는 서버면 된다). 여러 서버를 합친 Grafana 지표를 읽는 일은 남았다. 트리아지는 이미 실제 LLM 호출이고, 입력을 이슈 제목에서 스택트레이스로 넓히는 것이 다음 단계다.

## Ⅶ. 차별성 및 확장 가능성

**○ 기존 방식 또는 유사 서비스 대비 차별점**

- 기존 대시보드(Grafana·Sentry)는 숫자를 보여 주는 데서 끝난다. 이 프로젝트는 에이전트의 행동과 판단 근거를 보여 주고, 같은 화면에서 채팅으로 그 에이전트를 지휘한다.
- 운영자 에이전트(Codex)와 실행 에이전트(병정·OpenAI API)를 나눈 2층 구조다. 사람은 대화하고, Codex 가 명령으로 바꾸고, 병정이 실행한다.
- 의존성 없는 터미널 앱이라 SSH 접속 서버나 tmux 에서도 바로 뜬다. 게임 연출로 운영 흐름을 직관적으로 전달한다.

**○ 향후 기능 고도화 및 사용자·활용분야 확장 가능 내용**

- Grafana·Prometheus 쿼리로 여러 서버 트래픽 합산, 병정 하나를 실제 sentry-bot(Codex) 수정 런 하나에 연결해 진짜 MR 생성
- 트리아지 입력에 스택트레이스·관련 소스 추가, 실제 Sentry 이슈 수백 건으로 평가 확대
- Slack 알림, 웹 버전(같은 state.json 을 브라우저에서)
- 다른 테마·지표: 결제 실패 = 화재, 배포 = 썰매, CI 실패 = 눈사람 붕괴 등. 데이터 파이프라인·고객문의 큐로 확장

## Ⅷ. 프로젝트 실행 및 확인방법

| 항목 | 내용 |
|---|---|
| 접속 및 실행방법 | `git clone https://github.com/merrybugmas/merrybugmas && cd merrybugmas && python3 xmas_market.py --replay` (키·로그인 없이, 녹화된 실제 AI 판정으로 재생) |
| 테스트 계정 | 해당 없음 (로그인 없음) |
| 주요 확인기능 | 1분 시나리오: 아무 키 → 메뉴에서 WEB · Sentry 버그 · START → `b`(쥐 떼) → 병정 출동·처리 → `r`(잡은 쥐 기록) → `1`(트래픽) → `0`(개요). 다른 터미널에서 `./market tell 진저 보고`, `./market brief`. AI 모드: `export OPENAI_API_KEY=…` 후 실행하면 첫 로그에 "AI 병정 모드" 표시 |
| 권장 실행환경 | macOS / Linux, 256색 터미널 100x30 이상 (macOS · Python 3.9 에서 확인). Windows 는 WSL. Codex 연동은 tmux 권장 |
| 기타 유의사항 | **API 키 없이 AI 판정 보기**: `python3 xmas_market.py --replay` 로 실행하면, 녹화해 둔 실제 OpenAI 트리아지 결과(판정·근거·수정 요약)로 재생한다. `--replay` 를 빼면 AI 없는 키워드·mock 모드다. **실연동**(`--live`)은 본인 Sentry 토큰과 데모 서버(merrybugmas/demo-web)가 필요해 심사 환경에서는 시연영상으로 확인한다. 터미널의 "애매한 폭 문자를 2칸으로" 옵션은 끈다. API 키는 문서에 넣지 않으며, 키 없이도 전 기능이 키워드·mock 으로 동작한다. 테스트: `python3 -m unittest discover -s tests -v` |
